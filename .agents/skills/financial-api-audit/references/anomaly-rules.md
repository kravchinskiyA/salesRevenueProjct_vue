# Справочник правил аудита и классификации аномалий API

Данный документ описывает правила валидации ответов финансовых API (`finance1`, `finance2`, `currencyfreaks`), используемые скриптом аудита.

---

## 1. Категории строгости (Severity Levels)

| Уровень | Описание | Влияние на систему |
| :--- | :--- | :--- |
| 🔴 **CRITICAL** | Критические дефекты данных: нарушение базового типа, отрицательные суммы, отсутствие обязательных полей (`amount`, `currency`), неподдерживаемые валюты без курса. | Приводит к падению приложения, сбою расчёта выручки (`NaN`) или искажению финансового баланса. |
| 🟡 **WARNING** | Несоответствие контракту/спецификации: расхождения в регистре (`usd` вместо `USD`), поле `type` вместо `status`, нетипичные статусы транзакций (`rejected` вместо `failed`), лишние данные (`address` в корне ответа). | Требует хаков/адаптеров на фронтенде, увеличивает риск регрессий. |
| 🔵 **INFO** | Рекомендации по оптимизации: отсутствие заголовков кеширования (Cache-Control/ETag), избыточный размер payload, отсутствие пагинации при росте объёма данных. | Снижает производительность или удобство интеграции. |

---

## 2. Специфические проверки по источникам

### Источник 1 (`/api/finance1`)
- **Контракт верхнего уровня:** Корневой объект должен содержать только ключ `transactions: Array<Transaction>`.
- **Лишние поля (Data Leak / Pollution):** Наличие сторонних объектов (например, `address: { city, street, houseNumber }`) сигнализирует о нарушении принципа разделения доменов на бэкенде.
- **Именование полей:**
  - Поле статуса должно именоваться единым образом — `status` (в реальном API приходит `type`).
  - Должно присутствовать уникальное поле `id` для дедупликации и отслеживания транзакций.
- **Статусы транзакций:** Допустимые значения должны быть стандартизированы (например, `paid`, `pending`, `failed`, `cancelled`).
- **Регистр валюты:** Только ISO 4217 в верхнем регистре (`USD`, `EUR`, `GBP`).

### Источник 2 (`/api/finance2`)
- **Формат элемента:** Строка вида `"<amount> <CURRENCY>"`.
- **Регистр валюты:** Сервер часто присылает код в нижнем регистре (`300 usd`, `200 eur`). Это требует `toUpperCase()` на клиенте.
- **Разделители и локализация:** Должна использоваться точка как десятичный разделитель (`120.50`), недопустимы запятые или неразрывные пробелы.

### Курсы валют (`currencyfreaks.com`)
- **Наличие курса:** Любая валюта, упомянутая в `finance1` или `finance2`, обязана присутствовать в словаре `rates`.
- **Актуальность:** Поле `date` должно соответствовать запрашиваемому периоду.
