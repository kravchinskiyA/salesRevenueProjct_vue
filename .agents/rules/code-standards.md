# Правило: Стандарты кода и правила внесения изменений (Code Standards)

## Назначение
Обязательные требования к архитектурному стилю, чистоте кода и оптимизации при разработке компонентов и логики в проекте.

## 1. Vue 3 Composition API
- Все новые компоненты и рефакторинг существующих компонентов выполнять строго с использованием `<script setup>`.
- Использовать Composition API (`ref`, `computed`, `watch`, lifecycle hooks). Опциональный Options API запрещен.
- Обеспечивать явную типизацию пропсов и событий через `defineProps` и `defineEmits`.

## 2. Стилизация (Чистый CSS)
- Не подключать и не использовать TailwindCSS, Bootstrap или сторонние тяжелые CSS-фреймворки.
- Использовать Vanilla CSS и CSS Custom Properties (переменные темы), определенные в `src/style.css`.
- Поддерживать согласованность тёмной темы и адаптивной вёрстки для мобильных и десктопных экранов.

## 3. Разделение ответственности (SoC)
- **Сетевые вызовы:** Строго в `src/api/`. Никаких прямых вызовов `fetch`/`axios` внутри компонентов.
- **Валидация и нормализация данных:** В `src/services/validators.js` и `src/services/revenue.js`.
- **Запросы и кеширование:** Через composables с Vue Query в `src/composables/useRevenue.js`.
- **UI-компоненты:** Отвечают только за отображение, локальный UI-state и эмиссию событий.

## 4. Финансовая точность
- Все операции сложения, умножения на курсы и агрегации выручки производить исключительно через целочисленные центы (`toCents`, `fromCents`).

## 5. Оптимизация размера бандла (Code Splitting)
- Библиотека `xlsx` (SheetJS) является тяжелой. Её импорт разрешен **только динамически** в момент вызова экспорта:
  ```javascript
  const XLSX = await import('xlsx');
  ```
  Категорически запрещено добавлять синхронный импорт `import * as XLSX from 'xlsx'` в верхний уровень модулей, чтобы не раздувать начальный бандл приложения.
