# Архитектурная структура проекта salesRevenueProject

## 1. Общий обзор архитектуры

Проект построен по принципам многослойной модульной архитектуры (Layered Architecture) с четким разделением ответственности (Separation of Concerns).

```
   [Внешние API: Источники finance1/finance2, CurrencyFreaks]
                                 │
                                 ▼
                     [Транспорт: src/api/]
                  (fetchData, revenueApi.js)
                                 │
                                 ▼
                     [Слой сервисов и валидации: src/services/]
         (validators.js -> revenue.js -> revenueService.js)
                                 │
                                 ▼
                   [Слой серверного кеша: src/composables/]
                    (TanStack Vue Query: useRevenue.js)
                                 │
                 ┌───────────────┴───────────────┐
                 ▼                               ▼
       [Клиентское состояние: src/stores/]   [Слой утилит: src/utils/]
              (Pinia: period.js)           (date.js, format.js, export.js)
                 │                               │
                 └───────────────┬───────────────┘
                                 ▼
                   [Представления: src/views/]
          (DayView.vue, MonthView.vue, TransactionDetailView.vue)
                                 │
                                 ▼
                   [UI-компоненты: src/components/]
    (DateSwitcher, DayCharts, MonthCharts, ExportMenu, HeaderNav, TransactionModal)
```

## 3. Назначение и регламент слоев

### `src/api/` (Транспортный слой)
- **Ответственность:** Выполнение HTTP-запросов, формирование заголовков (`X-API-KEY`), первичный перехват HTTP-ошибок.
- **Ограничения:** Запрещено размещать вычисления выручки, конвертацию валют или состояние UI.

### `src/services/` (Бизнес-логика и домен)
- **Ответственность:**
  - `validators.js`: проверка контрактов входящих ответов от внешних систем.
  - `revenue.js`: нормализация разных форматов (`finance1` объект, `finance2` строки), строгий финансовый расчет сумм через центы (`toCents`/`fromCents`), фильтрация только успешных транзакций (`status === 'paid'`).
  - `revenueService.js`: оркестрация одновременной загрузки данных из источников и курсов валют через `revenueApi.js` с последующей агрегацией.

### `src/composables/` (Серверное состояние и кеширование)
- **Ответственность:** Обертка асинхронных операций в хуки TanStack Vue Query (`useDayRevenue`, `useMonthRevenue`).
- **Ограничения:** Управление временем устаревания (`staleTime`), ключами кеша и персистенцией в `localStorage`.

### `src/stores/` (Клиентское состояние)
- **Ответственность:** Управление состоянием UI, не связанным с сетевым кешем: выбранная дата/месяц в календаре, ограничения выбора дат в зависимости от флагов конфигурации.

### `src/utils/` (Утилитарные функции)
- **Ответственность:** Чистые функции без сайд-эффектов: парсинг и форматирование дат, форматирование денежных сумм, экспорт файлов.
- **Ограничения:** Экспорт Excel (`xlsx`) загружается исключительно асинхронно через `await import('xlsx')`.

### `src/views/` и `src/components/` (UI-слой)
- **Ответственность:** Реактивное отображение данных, обработка пользовательских действий, отображение графиков Chart.js.
- **Ограничения:** Запрещены прямые сетевые вызовы `fetch`. Данные получаются только через `composables` и `stores`. Стилизация строго на чистом CSS с использованием CSS-переменных из `src/style.css`.
